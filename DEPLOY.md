# Деплой Secret-bot: бот 24/7 + сайт, бесплатно

Документ отвечает на вопрос «куда положить бота, чтобы он работал всегда
и сайт был доступен», и описывает конкретные шаги для каждого варианта.

Проверено 21 октября 2026 года. Данные о тарифах меняются — перед
деплоем сверяйтесь со страницей хостинга.

---

## Что за сервис и что ему нужно

Secret-bot — это **один процесс**, в котором крутятся две вещи:

* **бот** (aiogram, long polling) — сам ходит в Telegram, публичный адрес
  ему не нужен;
* **сайт** (FastAPI + uvicorn) — отдаёт страницу расшифровки.

Разделить их на два сервиса нельзя: сайт отдаёт файл, **скачивая его из
Telegram** по `file_id` через `bot.download()`. Значит, у сайта должен быть
доступ к боту, а у бота — к общей базе. Проще держать вместе, и так уже
сделано.

Что сервису нужно от хостинга:

| Требование | Почему |
|---|---|
| **Живой 24/7** | long polling не отпускает, но если процесс спит — бот перестаёт отвечать |
| **Порт $PORT** | сайт слушает на порту, который задаёт платформа |
| **HTTPS** | без него **passkey (Face ID / отпечаток) не работает** вообще — это требование WebAuthn, а не наша прихоть |
| **Постоянный диск** | база SQLite: ссылки, passkey, мастер-ключ. Без диска после рестарта все ссылки мертвы |
| **Секреты в окружении** | `BOT_TOKEN` не должен лежать в коде |

Про постоянный диск стоит сказать отдельно: именно он решает, переживёт ли
ссылка рестарт. Потеря диска = потеря всех `file_id` = мёртвые ссылки,
которые уже разосланы людям.

## Варианты хостингов (сравнение)

Проверено 21.10.2026.

| Хостинг | 24/7 | Диск | HTTPS | Цена | Вердикт |
|---|---|---|---|---|---|
| **Northflank** (Sandbox) | да, **без засыпания** | том | да | $0 | **лучший вариант** |
| **Oracle Cloud** (Always Free) | да | 200 ГБ | да | $0 | мощно, но регистрация с картой и ожидание A1 |
| **Render** (Free) | **нет** (спит через 15 мин) | **нет** | да | $0 | не подходит: ещё и воркеров нет |
| **Hugging Face Spaces** | **нет** (спит) | эфемерный | да | $0 | не подходит |
| **Fly.io** | да | том | да | **от $2.19/мес** | бесплатного тарифа **больше нет** |
| **Koyeb** | да | — | да | **от $29/мес** | бесплатного тарифа **больше нет** |
| **Railway** | да | том | да | пробный $5 | после триала платно |
| **VPS** (Timeweb/DigitalOcean и т.п.) | да | да | да | от ~$3/мес | надёжно, но не бесплатно |

### Почему не Render (самое частое заблуждение)

Render Free действительно бесплатен, но:

1. **Сервис засыпает через 15 минут без запросов** и просыпается ~30–60 сек.
   Сайт пережил бы это, а **бот — нет**: long polling идёт к Telegram, а не
   от посетителя к сайту. Бот просто перестанет отвечать, пока сервис спит.
2. **Free-сервисы не имеют постоянного диска.** SQLite умер бы при каждом
   рестарте вместе со всеми ссылками.
3. **Background worker и cron на Free недоступны** — отдельный воркер для
   бота не задеплоишь.

### Почему не Fly.io и Koyeb

На 21.10.2026 у обоих **бесплатного тарифа не существует**:

* Fly.io — «Is there a free tier? **No.**» Минимум $2.19 за 30 дней
  непрерывной работы машины (shared-cpu-1x, 256 МБ RAM).
* Koyeb — бесплатный Sandbox заменён на **Pro от $29/мес** + compute.

Оба сайта прямо пишут об этом в прайсе, так что «старая» информация из
постов 2024–2025 тут больше не годится.

## Вариант 1: Northflank (рекомендуемый)

Единственный из бесплатных, который даёт **всё нужное сразу**: сервис не
засыпает, тома входят в тариф, HTTPS автоматический, $0.

Лимиты тарифа Sandbox: **2 бесплатных сервиса, 1 бесплатная база,
2 бесплатных cron-задачи**, compute — «Always-on-compute, no sleeping».

### Шаг 1. Зарегистрироваться

<https://app.northflank.com/signup> — GitHub/Google, без карты.
Тариф Sandbox выбирается по умолчанию.

### Шаг 2. Создать проект

<https://app.northflank.com/s/account/projects/new> — Northflank Cloud,
любой регион. Запомните **Project ID** (он в URL).

### Шаг 3. Создать сервис

1. **Add service → Deployment service** (не Job: Job выполняется один раз).
2. **Source**: Git repository → `TeivrimOriginal/Secret-bot`, ветка `main`.
   (Репозиторий публичный, так что приватный доступ не нужен.)
3. **Build**: Dockerfile. Путь — `Dockerfile` в корне репозитория.
   (Файл `secret-bot/Dockerfile` нужно скопировать в корень репозитория —
   см. «Что нужно закоммитить» ниже.)
4. **Runtime**:
   * **Instance type**: `nf-compute-200` (2 vCPU, 4 ГБ RAM) — самый маленький,
     который тянет Python + aiogram; `nf-compute-100` тоже подойдёт.
   * **Instances**: 1. Больше не надо: SQLite и long polling не масштабируются,
     а лимит всё равно два сервиса.
5. **Volume**: Add volume →
   * имя `secretbot-data`,
   * **Access mode: Single Read/Write** (сервис один, масштабировать не будем),
   * size 1 ГБ (хватит с запасом; SQLite + состояния),
   * **Volume mount path**: `/data`.
6. **Environment variables**:

   | Переменная | Значение | Обязательно |
   |---|---|---|
   | `BOT_TOKEN` | токен от @BotFather | **да** |
   | `BASE_URL` | `https://<домен-сервиса>` | **да** |
   | `ENABLE_WEB` | `1` | да |
   | `DB_PATH` | `/data/links.db` | да |
   | `PORT` | платформа задаёт сама | — |
   | `MAX_FAILS` | `5` | нет |
   | `FAIL_WINDOW` | `900` | нет |

   `BASE_URL` **обязателен**: из него берётся `rpId` для passkey и `origin`
   для WebAuthn. Если он не совпадёт с реальным адресом сайта, кнопки
   «Создать passkey» не появятся, а вход по Face ID будет отклонён
   браузером.

7. **Health check**: путь `/healthz`, порт = `$PORT`, ожидание 200.

8. **Create** → дождаться статуса Running.

### Шаг 4. Проверить

```bash
curl -sS https://<домен-сервиса>/healthz          # {"ok":true}
```

Потом откройте сайт с телефона: страница `/d/<token>` должна открыться,
а после ввода кодового слова — появиться кнопка **«Создать passkey»**.
Если кнопки нет — неверный `BASE_URL`.

### Шаг 5. Домен

Бесплатный адрес Northflank вида `https://<имя>-<id>.code.run` уже
работает и имеет HTTPS. Свой домен подключается в разделе Custom Domains
(сертификат выпускается автоматически) — но помните: **смените `BASE_URL`,
если адрес изменится**, иначе старые passkey перестанут работать (rpId
привязан к имени хоста).

## Вариант 2: Oracle Cloud Always Free

Бесплатно навсегда, и ресурсы щедрые: **Ampere A1 — 4 OCPU, 24 ГБ RAM,
200 ГБ диска**. Подойдёт, если хочется «настоящую» машину и полный
контроль.

**Но** сразу честно о сложностях:

* Регистрация требует **банковскую карту** (списывается ~$1 и возвращается).
* Free Tier даёт **$300 на 30 дней** — потом остаётся только Always Free.
* Машины A1 **часто недоступны** в регионах: «Out of host capacity».
  Приходится перебирать регионы и ждать. Это главная причина, по которой
  люди бросают этот путь.
* Нужен **свой сертификат** (Let's Encrypt) и **свой домен** — публичного
  адреса `*.oraclecloud.com` с нормальным HTTPS для passkey нет.

Порядок:

1. Регистрация: <https://www.oracle.com/cloud/free/>.
2. Создать VM: Compute → Instances → Ampere A1, 4 OCPU, 24 ГБ, Ubuntu 24.04.
   Скачать SSH-ключ.
3. Поднять контейнер:

   ```bash
   ssh -i <ключ> ubuntu@<ip>
   sudo apt update && sudo apt install -y docker.io
   git clone https://github.com/TeivrimOriginal/Secret-bot.git
   cd Secret-bot
   sudo docker build -t secretbot .
   sudo docker run -d --restart unless-stopped \
     --name secretbot \
     -p 80:8080 \
     -v /opt/secretbot-data:/data \
     -e BOT_TOKEN='<токен>' \
     -e BASE_URL='https://<ваш-домен>' \
     -e ENABLE_WEB=1 \
     -e DB_PATH=/data/links.db \
     secretbot
   ```

4. HTTPS: certbot + nginx как обратный прокси на `127.0.0.1:8080`.
   Passkey требует HTTPS — без него эта функция просто выключена.

## Вариант 3: бесплатный GitHub Actions (для теста, не для продакшена)

Для публичного репозитория GitHub Actions **бесплатен без ограничений**
(это подтверждено документацией: «usage is free for … public repositories
that use standard GitHub-hosted runners»).

Схема: workflow запускает `launcher.py` на раннере, а сайт открывается
через туннель.

**Ограничения, из-за которых это не «24/7»:**

* раннер работает **6 часов максимум** на job;
* workflow живёт, пока есть активность; по умолчанию без событий он не
  стартует — нужен `schedule` или внешний пинг;
* база живёт только в пределах job — **ссылки не переживают перезапуск**,
  если не класть её в артефакт или в внешнее хранилище.

То есть это способ «покрутить и посмотреть», а не способ «оставить
работать». Для продакшена — вариант 1 или 2.

## Что нужно закоммитить в репозиторий

Northflank собирает из **корня** репозитория, а код лежит в подпапке
`secret-bot/`. Нужно:

```bash
cd secret-bot
cp Dockerfile ../Dockerfile.secretbot   # или перенести Dockerfile в корень
```

Проще: сделать в корне репозитория `Dockerfile`, который копирует код из
`secret-bot/`:

```dockerfile
FROM python:3.12-slim-bookworm
WORKDIR /app
COPY secret-bot/requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt
COPY secret-bot/*.py ./
COPY secret-bot/static ./static
ENV DB_PATH=/data/links.db ENABLE_WEB=1 WEB_HOST=0.0.0.0
RUN mkdir -p /data && chmod 777 /data
EXPOSE 8080
CMD ["python", "-u", "launcher.py"]
```

То же самое делает `render.yaml` / `northflank.yaml`, если решено
использовать декларативный конфиг вместо веб-интерфейса.

## Проверка перед деплоем

```bash
cd secret-bot
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python launcher.py --selftest    # 14 проверок, exit 0
.venv/Scripts/python -m pytest tests -q        # тесты хранилища состояний
```

`--selftest` проверяет всё, что можно проверить без Telegram: шифрование,
базу, сайт, 404, PWA. Если он зелёный, код рабочий.

## Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Сервис не отвечает, в логах «address already in use» | Платформа задаёт порт в `PORT`, а код слушал на 8080 | `WEB_PORT`/`PORT` теперь читаются оба — проверить, что переменная дошла |
| Кнопки passkey не появляются | `BASE_URL` не совпадает с адресом сайта | Проверить `BASE_URL`, включая схему (`https://`) |
| После рестарта ссылки мертвы | нет постоянного тома | Подключить том и положить базу на него (`DB_PATH=/data/links.db`) |
| Бот перестал отвечать через несколько минут | сервис заснул (Render/HF) | Перейти на Northflank — там не засыпает |
| `bot.download()` падает | токен неверный или сеть до api.telegram.org закрыта | Проверить `BOT_TOKEN`; в контейнере должен быть доступ к `api.telegram.org` |
| Файл в группе не шифруется | бот не админ — нет права удалять сообщения | Выдать боту права администратора в группе |
