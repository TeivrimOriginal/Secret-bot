# Secret-bot — расшифровка файлов по ссылке + passkey

Telegram-бот (aiogram) шифрует файлы паролем и выдаёт кликабельную ссылку
на веб-страницу. На странице человек вводит кодовое слово — либо один раз
создаёт **passkey** и дальше входит по отпечатку / Face ID / Windows Hello.
Сайт работает на **FastAPI**, бот — long polling, оба в одном процессе.

```
secret-bot/
├── config.py         настройки из переменных окружения (ничего не делает)
├── crypto.py         AES-256-GCM + PBKDF2: синхронные функции и await-обёртки
├── database.py       SQLite: ссылки, группы, passkey, обёрнутые кодовые слова
├── fsm_storage.py    состояния бота в той же SQLite — переживают перезапуск
├── passkey.py        разбор WebAuthn и подписанные куки grant/сессия
├── private.py        хендлеры личного чата (пароль от пользователя)
├── groups.py         хендлеры групп (кодовое слово группы + ссылка)
├── crypt_bot.py      сборка роутеров, запуск сайта и polling
├── web_app.py        сайт на FastAPI: страница, выдача файла, эндпоинты passkey
├── launcher.py       точка входа (--version, --selftest, конфиг secret-bot.env)
├── Dockerfile        образ для деплоя на PaaS
├── tests/            pytest: хранилище состояний, проверка Dockerfile
├── scripts/          verify_dockerfile.py — проверка образа без Docker
├── build/            сборка .exe и установщика (см. «Сборка и установка»)
├── DEPLOY.md         как развернуть на бесплатном хостинге
└── README.md         этот файл

(в корне рабочего репозитория)
test-passkey.py        82 проверки: юнит WebAuthn + сквозной HTTP через FastAPI
pw-demo-server.py      тот же сайт без Telegram — для проверки в браузере
```

Модули лежат слоями и тянут друг друга только вниз: `config` ни от кого не
зависит, `crypto` знает только `config`, `database` — `config` и `crypto`,
`fsm_storage` — `config`, `passkey` — `database`, `web_app` — `config`,
`crypto`, `database`, `passkey` и **не знает про бота** вообще: сайту нужны
ключ для расшифровки и ссылка, а не Telegram-логика. Бот (`crypt_bot.py`)
собирает `private` + `groups` и поднимает сайт.

## Запуск

```bash
pip install -r requirements.txt

export BOT_TOKEN=123456:AA...            # токен от @BotFather
export BASE_URL=https://files.example.com # публичный адрес сайта, без слеша
export ENABLE_WEB=1                       # включить сайт (по умолчанию выключен)
export WEB_HOST=0.0.0.0 WEB_PORT=8080
python launcher.py
```

`launcher.py` — рекомендуемая точка входа: он читает файл `secret-bot.env`
(если он есть рядом или в текущем каталоге), умеет `--version` и
`--selftest`, и в собранном `.exe` он же выбирает каталог для базы.
Запуск `python crypt_bot.py` напрямую тоже работает, но тогда все настройки
нужно задавать только переменными окружения.

Проверка без Telegram (страница на localhost:8099, слово `demo-codeword-1`):

```bash
python pw-demo-server.py     # http://localhost:8099/d/demo-token-1
python launcher.py --selftest
python test-passkey.py       # 70 проверок, exit=0
```

`test-passkey.py` гоняет HTTP через `fastapi.testclient`, то есть ему нужен
`httpx`. Starlette 1.7 при этом печатает `StarletteDeprecationWarning`
(«install `httpx2` instead») — это только предупреждение, тесты зелёные;
лечится `pip install httpx2`.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `BOT_TOKEN` | — | токен бота от @BotFather |
| `BASE_URL` | `http://localhost:8080` | публичный адрес сайта; из него берутся rpId и origin WebAuthn |
| `ENABLE_WEB` | `0` | поднимать ли сайт (бот без сайта всё равно шифрует и даёт ссылки) |
| `WEB_HOST` / `WEB_PORT` | `0.0.0.0` / `8080` | где слушает сайт. `WEB_PORT` пуст — берётся `PORT` (так задают порт все PaaS) |
| `PORT` | — | если задан, используется как порт сайта: Render, Northflank, Railway и Fly задают порт именно так |
| `DB_PATH` | `links.db` | файл SQLite со ссылками, ключами и passkey |
| `FSM_TTL` | `3600` | сколько живёт состояние бота (в нём лежит файл, ждущий пароля) |
| `ENABLE_PASSKEY` | `1` | показывать ли кнопки passkey на странице |
| `PW_GRANT_TTL` | `600` | сколько секунд после верного слова открыта регистрация passkey |
| `PW_CHALLENGE_TTL` | `300` | срок жизни одноразового challenge |
| `PW_SESSION_TTL` | `2592000` (30 суток) | сколько живёт вход по passkey |
| `MAX_FAILS` / `FAIL_WINDOW` | `5` / `900` | сколько неверных слов терпит ссылка и за какой период |
| `SECRET_BOT_ENV` | — | путь к файлу настроек; иначе ищется рядом с программой, в текущем каталоге и в `%APPDATA%\SecretBot` |
| `LOG_LEVEL` | `INFO` | уровень логов |

Порт по умолчанию 8080; на машине разработки он занят Steam
(`steamwebhelper.exe`), поэтому демо-сервер слушает 8099.

## Как это работает

### Личный чат
1. Присылаете документ — бот определяет режим по маркеру `CRYPTv1\0`.
2. Вводите пароль.
3. Бот отдаёт результат и (для шифрования) кликабельную ссылку
   `<a href="BASE_URL/d/<token>">` — явный HTML-якорь, parse_mode=HTML,
   поэтому клик работает всегда, а не только когда Telegram узнаёт URL.

### Группа (бот — админ с правом удаления)
1. Админ заранее пишет боту в личку `/setcode`, выбирает группу, задаёт её
   кодовое слово (хранится в SQLite).
2. Участник присылает незашифрованный документ — бот читает его, удаляет
   оригинал, шифрует кодовым словом группы, присылает `.enc` и ссылку.
3. Уже зашифрованные файлы (с маркером) бот в группе не трогает.

Ссылка в подписи группы — обычный текст `🔗 https://...`: Telegram сам
превращает такой URL в кликабельный. В личке используется явный `<a href>`,
потому что там подпись длиннее и ссылка может потеряться среди текста.

### Формат файла
```
[8 байт "CRYPTv1\0"][16 байт соли][12 байт nonce][шифртекст + тег GCM]
```
Ключ — PBKDF2-HMAC-SHA256, 600 000 итераций; шифр — AES-256-GCM.

### Passkey (WebAuthn)
1. Человек открывает ссылку и один раз вводит кодовое слово — файл
   скачивается, браузеру ставится короткая «печать» (grant-кука, 10 минут).
2. Появляется кнопка «Создать passkey»: браузер подтверждает биометрией/PIN
   и отдаёт серверу публичный ключ. Аттестат (`attStmt`) **не** проверяется —
   модель угрозы другая, доступ держит кодовое слово.
3. В этот же момент в таблицу `vault` кладётся обёрнутая ключом сервера копия
   кодового слова — иначе файл было бы нечем расшифровать при входе с другого
   устройства (браузер приватный ключ не отдаёт). Без регистрации passkey
   копия живёт только в памяти и в базу не попадает.
4. Дальше кнопка «Войти по Face ID / отпечатку»: сервер выдаёт challenge,
   браузер подписывает его приватным ключом, сервер проверяет подпись и ставит
   сессионную куку на 30 суток. Файл отдаётся по `GET /d/<token>/get` уже без
   кодового слова.

Проверяется при регистрации и входе: тип `clientData`, одноразовость
challenge (таблица `challenges`), origin, `rpIdHash`, флаги UP и UV
(`userVerification: required`), подпись ES256/RS256, счётчик (отказ при
клоне ключа).

## Маршруты сайта (FastAPI)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | заставка: вставить ссылку из Telegram (её открывает Android-обёртка) |
| GET | `/d/{token}` | страница ввода кодового слова и кнопок passkey |
| POST | `/d/{token}` | проверка слова, выдача расшифрованного файла, grant-кука |
| GET | `/d/{token}/get` | файл после входа по passkey |
| POST | `/d/{token}/pw/register/options` | challenge для создания passkey |
| POST | `/d/{token}/pw/register/verify` | сохранить passkey и ключ ссылки |
| POST | `/d/{token}/pw/login/options` | challenge для входа |
| POST | `/d/{token}/pw/login/verify` | проверить подпись, выдать сессию |
| GET | `/healthz` | проверка, что сайт жив |

Архитектурная деталь: uvicorn запускается как asyncio-задача в том же цикле,
что и polling (`crypt_bot.main()`). Вынести сайт в отдельный поток нельзя:
aiohttp-сессия Telegram создаётся в цикле бота, и вызов `bot.download()` из
чужого цикла сломал бы выдачу файла. Сигналы главного цикла при этом
обрабатывает aiogram, поэтому у uvicorn перехват сигналов отключён.

## Соответствие ТЗ (исходный crypt_bot.py)

Исходный бот умел: шифровать/расшифровывать файлы в личке, групповой режим с
кодовым словом группы и удалением оригинала, страницу `/d/{token}` с вводом
слова и выдачей файла, ограничение неверных попыток. Всё это сохранено;
ниже — что добавлено и что изменилось.

| Требование | Статус | Комментарий |
|---|---|---|
| Шифрование/расшифровка в личке | ✅ сохранено | алгоритм и формат файла не менялись |
| Групповой режим (`/setcode`, удаление оригинала) | ✅ сохранено | `database.add_link` для зашифрованного файла на месте |
| Страница `/d/<token>` (ввод слова, выдача файла) | ✅ сохранено | интерфейс тот же, веб-слой переведён на FastAPI |
| Ограничение неверных попыток | ✅ сохранено | `MAX_FAILS=5` за 15 минут на ссылку; теперь читается из окружения |
| Кликабельные ссылки в сообщениях | ✅ добавлено | `<a href>` в личке, обычный URL в группе (Telegram делает его кликабельным) |
| Вход по отпечатку/Face ID (passkey) | ✅ добавлено | WebAuthn ES256/RS256, UV обязателен |
| Проверка аттестата (`attStmt`) | ⚠️ умышленно нет | доступ держит кодовое слово, не подлинность устройства |
| Хранилище FSM | ✅ исправлено | было `MemoryStorage` — состояния и лежащие в них файлы терялись при перезапуске. Теперь `fsm_storage.SQLiteStorage`: состояние лежит в той же базе и переживает рестарт процесса (на PaaS перезапуск — обычное дело) |
| Разбивка на модули | ✅ добавлено | `config`/`crypto`/`database`/`passkey`/`private`/`groups`; сайт не знает про бота |
| Документация | ✅ этот README + DEPLOY.md | |

Отличие по ошибкам: неизвестная ссылка теперь отдаёт 404 (в исходнике
`rec[1]` на `None` давал 500), а ошибка скачивания из Telegram на странице
ввода слова приводится к «Внутренняя ошибка» вместо отдельного текста.

## Безопасность

- Кодовое слово никогда не попадает в браузер: приватный ключ passkey остаётся
  на устройстве, сервер хранит только публичный.
- Копия кодового слова в `vault` зашифрована ключом сервера (AES-GCM), а сам
  мастер-ключ лежит в той же базе (`settings`) — при краже файла БД он тоже
  уедет. Это осознанный компромисс ради входа с чужого устройства.
- Куки `httponly`, `samesite=lax`, `secure` при HTTPS; и `grant`, и сессия
  подписаны HMAC и проверяются по `exp` из самой куки.
- Для продакшена: HTTPS обязателен (без него WebAuthn не работает),
  `MemoryStorage` стоит заменить на `RedisStorage`, а `DB_PATH` держать вне
  публичного каталога.

## Сборка и установка (Windows)

Готовый установщик ничего не требует от пользователя: Python и все
библиотеки внутри, права администратора не нужны.

### Для пользователя

```
SecretBot-<версия>-setup.exe          установщик (ярлыки, конфиг, удаление)
SecretBot-<версия>-portable.zip       то же без установки, распаковать и запустить
```

Что делает установщик:

* кладёт программу в `%LOCALAPPDATA%\Programs\Secret-bot`;
* создаёт шаблон настроек `%APPDATA%\SecretBot\secret-bot.env` и предлагает
  его открыть (`BOT_TOKEN` и `BASE_URL` нужно вписать руками);
* делает ярлыки: запуск, настройки, «Проверить сборку», папка с данными;
* при удалении сносит программу и ярлыки, но **не** трогает
  `%APPDATA%\SecretBot` — там ключи ссылок и passkey.

Проверка без Telegram:

```
SecretBot.exe --selftest     крипто, база, сайт, страница, 404
SecretBot.exe --version
```

### Для разработчика

Нужны `pyinstaller` и Inno Setup 6 (для установщика):

```
pip install -r requirements.txt pyinstaller
python build\build.py
```

`build/build.py` по шагам: создаёт иконку, компилирует исходники, гоняет
`--selftest` из исходников, собирает onedir-сборку через PyInstaller,
гоняет `--selftest` уже у собранного `.exe` и упаковывает всё установщиком
Inno Setup. Версия берётся из `launcher.py` — один источник правды, менять
только там.

Затем артефакты:

```
python build\release.py             портативный zip + SHA256SUMS.txt
python build\release.py --publish   ещё и релиз на GitHub (через gh)
```

Файлы сборки:

| Файл | Назначение |
|---|---|
| `build/secret-bot.spec` | описание сборки PyInstaller (onedir) |
| `build/installer.iss` | сценарий Inno Setup |
| `build/build.py` | оркестрация сборки |
| `build/release.py` | портативный zip, контрольные суммы, публикация |
| `build/make-icon.py` | рисует `secret-bot.ico` (без готовых ассетов) |

Грабли, на которые уже наступили (чтобы не повторять):

* **`unittest` нельзя исключать** из сборки: aiogram делает
  `from unittest.mock import sentinel`, и без него exe падает на импорте
  `crypt_bot` (`ModuleNotFoundError: No module named 'unittest'`).
* **onedir, а не onefile**: uvicorn и fastapi тянут много подпакетов, и
  onefile распаковывается при каждом старте. Установщик всё равно один файл.
* **`--selftest` обязателен в сборке**: обычный запуск требует живого
  `BOT_TOKEN`, поэтому без самотеста frozen-сборку нечем проверить.
* Сборка на Python, а не на PowerShell: Windows PowerShell 5.1 в этом
  окружении спотыкался на скриптах с кириллицей.

## Android

Путь без сборки: страница уже адаптивная, а для Android у неё есть поддержка
PWA — манифест, service worker и иконки (`/manifest.webmanifest`, `/sw.js`,
`/icon-*.png`), поэтому Chrome предложит **«Добавить на главный экран»**,
и страница появится как ярлык и откроется без адресной строки.

Если нужен настоящий apk (иконка в лаунчере, открытие ссылок извне), есть
обёртка в `android/` — это WebView над той же страницей: подробности,
команда сборки и список того, что в ней проверено, в `android/README.md`.

Что учесть в любом случае:

* **Сайт открывается по адресу, а ссылка — с токеном.** На главной (`/`)
  есть заставка: вставьте ссылку из Telegram — откроется нужная страница.
  Без неё обёртка, спросив адрес сайта, показывала 404.
* **WebAuthn требует HTTPS.** На `http://` кнопки passkey не появятся.
  `http://localhost` — исключение (браузер считает его безопасным), поэтому
  локальная проверка работает и без сертификата.
* **WebView не умеет скачивать `blob:`**, поэтому в обёртке файл сохраняет
  мост из страницы. В PWA и в браузере всё работает штатно.
* **Запуск самого бота на Android** — через [Termux](https://termux.dev):
  `pkg install python`, затем `pip install -r requirements.txt` и
  `python launcher.py`. Бот должен быть запущен там, где до него есть сеть,
  а сайт — там, где его открывают люди. Обычно это разные машины, поэтому
  проще держать бота на компьютере или сервере, а на Android открывать ссылку.

## Публичный URL

### Деплой на Render.com (Render.yaml)

Для быстрого и бесплатного хостинга можно использовать **Render.com**.  Файл `render.yaml` уже добавлен в корень репозитория и описывает сервис:

```yaml
services:
  - type: web
    name: secret-bot
    env: docker
    plan: free
    region: oregon
    dockerfilePath: Dockerfile
    autoDeploy: true
    envVars:
      - key: BOT_TOKEN
        value: ${BOT_TOKEN}
      - key: BASE_URL
        value: ${BASE_URL}
      - key: ENABLE_WEB
        value: "1"
```

1. Зарегистрируйтесь/войдите в Render.com.
2. На странице **New → Web Service** выберите **Connect a repository** и укажите этот репозиторий.
3. Render автоматически обнаружит `render.yaml`, создаст сервис и запустит сборку Docker‑образа.
4. После успешного деплоя в переменных окружения сервиса задайте `BOT_TOKEN` (токен от BotFather) и `BASE_URL` – публичный URL, который будет использоваться сайтом (например, `https://secret-bot.onrender.com`).
5. Сервис будет работать 24/7, а GitHub Actions будет автоматически пушить новые версии Docker‑образа в GitHub Container Registry.

---

*Обратите внимание*: При первом запуске без `BASE_URL` бот будет работать только в режиме без сайта. Чтобы включить веб‑интерфейс, установите `ENABLE_WEB=1` и укажите корректный `BASE_URL`.


Бот работает на **long polling** — ему публичный адрес не нужен, он сам
дёргает Telegram. Публичный адрес нужен только **сайту** (странице расшифровки),
и для passkey он обязан быть по HTTPS.

Варианты, от быстрого к постоянному:

| Способ | HTTPS | Нужна регистрация | Как запустить |
|---|---|---|---|
| cloudflared | да | нет | `cloudflared tunnel --url http://localhost:8080` |
| localtunnel | да | нет | `npx localtunnel --port 8080` |
| ngrok | да | да | `ngrok http 8080` |
| свой домен + сертификат | да | да | nginx + certbot на сервере |
| бесплатный хостинг | да | да | **Northflank** (тариф Sandbox) / Oracle Cloud Always Free |

Для разовой проверки проще всего **cloudflared** или **localtunnel**: никакой
регистрации, команда — и вы получаете ссылку вида `https://что-то.trycloudflare.com`,
которую можно сразу вписать в `BASE_URL` и открыть с телефона.

Для постоянной работы нужен адрес, который не меняется:  — бесплатный хостинг
с доменом или свой сертификат. Иначе после перезапуска туннеля ссылка в
`BASE_URL` станет нерабочей, а старые ссылки в Telegram перестанут открываться.

Проверить, что адрес правильный: откройте его с телефона и убедитесь, что
кнопка «Создать passkey» появляется после ввода кодового слова.

## Деплой на хостинг (24/7 + сайт)

Полная инструкция со сравнением тарифов — в **[DEPLOY.md](DEPLOY.md)**.
Коротко:

```bash
# Проверить, что всё в порядке, до деплоя
python launcher.py --selftest      # 14 проверок без Telegram
python -m pytest tests -q          # тесты хранилища и Dockerfile
python scripts/verify_dockerfile.py

# Собрать и запустить (нужен Docker)
docker build -t secretbot .
docker run -d --restart unless-stopped \
  -p 8080:8080 \
  -v secretbot-data:/data \
  -e BOT_TOKEN='<токен от @BotFather>' \
  -e BASE_URL='https://<ваш-домен>' \
  -e ENABLE_WEB=1 \
  -e DB_PATH=/data/links.db \
  secretbot
```

Что важно помнить при деплое:

* **`BASE_URL` обязан совпадать с реальным адресом сайта** — из него
  берётся `rpId` для passkey. Не совпадёт — кнопки входа по Face ID
  не появятся, а браузер отклонит проверку подписи.
* **База должна лежать на постоянном томе** (`/data/links.db`). Без тома
  после рестарта пропадут все ссылки, которые уже разосланы людям.
* **Порт задаёт платформа** — код читает и `WEB_PORT`, и `PORT`.
* **Сервис не должен засыпать**: на Render Free и Hugging Face Spaces
  он спит через 15 минут, и бот на это время перестаёт отвечать.

## Состояния бота переживают перезапуск

Раньше состояния бота жили в памяти (`MemoryStorage`). В состоянии лежит
не только «какой сейчас режим», но и **сам файл**: бот положил байты в
состояние и ждёт пароля.

На рабочей машине это незаметно. На PaaS — нет: процесс перезапускается
при каждом деплое, и человек, отправивший файл минуту назад, получал бы
ошибку вместо ввода пароля. Файл при этом оставался в Telegram — терялся
не он, а путь к нему.

Теперь состояние лежит в той же SQLite (`fsm_storage.py`), что и ссылки,
и переживает перезапуск. Это проверяется тестом
`tests/test_bot_e2e.py`: фейковый Telegram API, настоящий бот, настоящий
сайт — весь путь от документа до скачанного файла.
